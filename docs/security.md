# Security and release gates

## Data minimization

The app stores Shopify customer/order GIDs and financial aggregates only. It
does not persist customer name, email, phone, or address. Compliance webhooks
redact tenant/member data. Webhook payload retention is limited to 30 days and
audit logs to 12 months.

## Authentication

- Admin routes: Shopify admin session.
- Webhooks: Shopify HMAC through the framework authenticator.
- App proxy: Shopify signed proxy request; identity comes only from
  `logged_in_customer_id`.
- Customer API: Shopify Customer Account bearer session token; identity comes
  only from token `sub`.
- Redemption: session token plus idempotency key.

Customer Account extensions execute from a sandboxed/null origin. The Shopify
framework CORS helper must provide the response headers required by that
platform; do not add a generic application-wide `Access-Control-Allow-Origin:
*` policy.

## Release gates

- Typecheck, lint, unit tests, RLS integration tests, and React Router build.
- Shopify CLI Function schema generation/build after Partner app linking.
- Rust tests and instruction-count review for both Functions.
- Storefront JavaScript below 20 KB gzip and measured CLS below 0.05.
- Cross-shop access test with two development stores.
- Invalid HMAC/signature/session-token tests.
- Dependency audit review.

As of the implementation snapshot, the package registry reports upstream
advisories in the React Router 7/Shopify template toolchain. Do not suppress
them. Re-run `npm audit --omit=dev` before release and upgrade only to versions
supported by `@shopify/shopify-app-react-router`; record any accepted risk.

## Production prerequisites not stored in Git

- Partner app IDs and Function schemas generated by Shopify CLI.
- Protected Customer Data approval.
- Managed pricing configuration.
- Production DNS/TLS.
- Secret values.
- Backup/WAL destination credentials.
- Monitoring and incident notification destinations.
